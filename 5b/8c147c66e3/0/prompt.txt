## Findings

### 1. The config comment answers #283's question in the wrong direction — refinement, 75

`/home/scottdensmore/Developer/scottdensmore/contoso/apps/web/vitest.config.mts:21-23`

```
// #283 asked whether raising this hides the signal that a test is slow, and
// it does: `npm test` here is `vitest run` with the default reporter, which
// prints per-test durations for failures only, so on a green run the 20
// tests over 300ms are invisible at any timeout.
```

Every factual claim after the colon is true — I confirmed all of them above. The problem is `and it does`. The question is whether *raising the timeout* hides the signal, and the evidence you then give ("invisible at any timeout") establishes that raising it changes nothing: the signal was never emitted at 5000ms either. So the comment states the causal conclusion the rest of the sentence refutes.

The scenario where that bites: someone reading this line in six months to decide whether to raise the timeout again — or to justify lowering it — takes away "raising the timeout cost us the slow-test signal", which is the false premise the first version of this comment carried and which you already corrected once. This is the same overstatement class, surviving in the connective rather than in the claim.

Suggested fix: `and it does not — the signal is absent either way:` (or `and it was never there:`), leaving the rest of the sentence untouched.

### 2. The docblock's "what nothing here catches" list omits deletion of `retry: 0` — refinement, 75

`/home/scottdensmore/Developer/scottdensmore/contoso/apps/web/src/test/runner-budget.test.ts:16-29`

The mutation table records the timeout deletion case (`testTimeout` line deleted → fails, reporting 5000) but for retry lists only value changes. Deletion behaves differently for the two keys: unset `testTimeout` falls back to 5000 and the budget assertion fails, whereas unset `retry` resolves to `undefined`, `getRetryCount(undefined)` returns 0, and `retries nothing` **passes**. So if someone removes the `retry: 0` line, this guard stays green.

That is not wrong as an assertion — the effective policy is still zero retries, which is what the test claims. But it is the one thing the sibling `tests/scripts/test_e2e_journey_wiring.py::test_retries_are_not_enabled` does catch for the journeys, and the config comment's stated purpose for the line ("so that turning it on is a visible decision rather than a line nobody wrote") depends on the line being there. The root `AGENTS.md` step 4 requires writing down which mistakes nothing catches, and the docblock has that section, so the omission is a gap in exactly the list the rule asks for.

Suggested fix: add a line to the *What nothing here catches* paragraph — removal of `retry: 0` itself, since vitest's default resolves to the same zero and the assertion is on effective policy rather than on the declaration.
